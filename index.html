How It Works

A four-stage ML pipeline that turns a raw URL string into a safe/phishing classification.

01 / INPUT
🔗
URL Ingestion

Raw URL is parsed using Python's urllib.parse into protocol, domain, path, query, and fragment components.

02 / FEATURES
⚙️
Feature Extraction

17+ structural features per component — length, dot count, slash count, hyphens, special characters like @, ?, =, #, $ and more.

03 / SCALING
📐
Normalization

All numeric features are scaled to [0,1] using MinMaxScaler before feeding into classifiers.

04 / PREDICT
🧠
Classification

XGBoost model (99% accuracy) outputs binary classification: Legitimate URL or Phishing URL, with high precision and recall.

// extracted url features

Feature Engineering

Each URL component is analyzed for 17+ structural signals. These features alone — with no content inspection — achieve 99% accuracy.

📏
URL Length

Phishing URLs are typically longer to hide malicious intent behind legitimate-looking paths.

·
Dot Count

Excess dots in domain/path signal subdomain abuse (e.g. paypal.secure.evil.com).

@
@ Symbol

Presence of @ in a URL forces browsers to ignore the preceding part — a classic phishing trick.

?
Query Parameters

Excessive query params with token/session/id keys are common in phishing redirect chains.

🔒
HTTPS Usage

Protocol detection — phishing sites often skip HTTPS or use HTTP to avoid certificate costs.

—
Hyphen Count

Domains like paypal-secure-login.com use hyphens to mimic legitimate brands.

/
Slash Count

Deep nested paths with many slashes often mask phishing endpoints within long URLs.

+14
More Special Chars

14 additional character-level features: #, $, %, !, ~, +, *, &, =, space, comma, and more.
